PART 1: THE BIG PICTURE - HOW THE 4 PIECES WORK TOGETHER
--------------------------------------------------------------------------------

1. GITHUB (The Code Storage):
   - Stores your source code in the cloud.
   - When you push new code to GitHub, Vercel and Render automatically detect it.

2. VERCEL (The Frontend Host):
   - Hosts your React / Vite website (HTML, CSS, JavaScript).
   - What users see and interact with in their web browser.
   - Fast, global CDN.

3. RENDER (The Backend Host):
   - Runs your Node.js + Express API server (index.js).
   - Handles login, orders, payments (Razorpay), emails, and business logic.
   - Talks directly to MongoDB Atlas.

4. MONGODB ATLAS (The Database):
   - Stores your real data: books, users, passwords, orders, reviews.
   - Protected by Username/Password and Network Access (IP Whitelist).

PART 3: COMMON DEPLOYMENT TERMS EXPLAINED IN SIMPLE WORDS
--------------------------------------------------------------------------------

1. IP Address:
   - Like a phone number for computers on the internet.
   - Your laptop has an IP; Render's cloud servers have their own IPs.

2. Whitelist / Access List:
   - A VIP guest list. If an IP is on the list, the database allows it in.
   - 0.0.0.0/0 means "open to anyone with the correct password".

3. Port:
   - Like an apartment door number inside a building.
   - Frontend runs on :8080 or :3000 locally.
   - Backend runs on :5000 locally, and :10000 on Render.

4. Environment Variables (.env):
   - Secret settings (passwords, API keys, database URLs) kept out of GitHub.
   - You must type them manually into Render and Vercel settings dashboards.

5. CORS (Cross-Origin Resource Sharing):
   - A browser security rule that asks: "Is website A (Vercel) allowed to ask
     for data from backend B (Render)?"
   - The backend must say YES in cors() configuration.

6. Build Command vs Start Command:
   - Build Command: How to install/prepare files (e.g., 'npm install').
   - Start Command: How to run the server continuously (e.g., 'node index.js').

7. Root Directory:
   - Which folder has the files Render or Vercel should run.
   - If your backend is inside a folder named 'server', Root Directory = 'server'.

PART 5: STEP-BY-STEP DEPLOYMENT RECIPE (YOUR CHEAT SHEET)
--------------------------------------------------------------------------------

Step 1: MongoDB Atlas
  - Create free M0 cluster.
  - Create Database User (save username & password).
  - Add 0.0.0.0/0 to Network Access.
  - Copy Connection String URI.

Step 2: Push code to GitHub
  - git add .
  - git commit -m "update code"
  - git push origin main

Step 3: Render (Backend)
  - New Web Service -> Select GitHub Repo.
  - Root Directory: server
  - Build Command: npm install
  - Start Command: node index.js
  - Add Environment Variables (MONGO_URI, JWT_SECRET, etc.).
  - Copy the live Render backend URL (e.g. https://your-api.onrender.com).

Step 4: Vercel (Frontend)
  - Add New Project -> Import GitHub Repo.
  - Add Environment Variable: VITE_API_URL = https://your-api.onrender.com
  - Deploy.
  - Test login, books, and orders!
